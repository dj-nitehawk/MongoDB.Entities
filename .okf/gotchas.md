# Gotchas

- **Tests need Mongo.** Default path expects compose on `localhost:27017` with `admin`/`password`, `rs0`, `authSource=admin`. Without it, use `MONGODB_ENTITIES_TESTCONTAINERS=1` (Docker required).
- **Replica set required** for multi-doc transactions and related tests; standalone Mongo will fail those cases.
- **Replica set member host must be host-reachable.** Tests connect with `localhost:27017` + `replicaSet=rs0`. After hello/isMaster the driver follows the advertised member host. If `rs.initiate` used the compose service name (`mongodb:27017`), host-side clients get `Name or service not known` / server selection timeout on `Unspecified/mongodb:27017`. Use `localhost:27017` (as in `docker-compose.ci.yml`) or reconfig: `cfg.members[0].host='localhost:27017'; rs.reconfig(cfg,{force:true})`.
- **`Tests/.mongo-keyfile`:** compose mounts it; CI creates with `chmod 600` and `chown 999:999`. Wrong perms → container auth/keyfile errors.
- **`[assembly: DoNotParallelize]`**: do not enable parallel MSTest without redesigning shared DB usage.
- **`Many<>` uninitialized** → runtime failures; call `InitOneToMany` / `InitManyToMany` before access, normally in the entity constructor (see relationship wiki/tests).
- **Tenant-specific relationships:** initializers default to `DB.Default`. Explicitly pass the intended `DB` and rebind after deserialization before relationship access. A model may deliberately leave `Many<>` uninitialized until this explicit binding; see `Documentation/wiki/Multiple-Databases.md`.
- **Save-hook timing is not an insert detector:** single-entity `SaveAsync` invokes `OnBeforeSave` before ID preparation; batch saves, partial saves, and inserts invoke it afterward. Use explicit application state for creation-only logic, not an empty ID inside the hook.
- **Count filter bypass:** `CountAsync` honors its per-call `ignoreGlobalFilters` argument, not `DB.IgnoreGlobalFilters`. Estimated counts and raw collection access bypass entity global filters.
- **Watcher registries** are keyed by DB instance and entity type; watcher names are trimmed and lowercased. `MaxConnectionPoolSize` tunes connections, not the .NET thread pool.
- **Wiki conversion examples:** `DateTime` and `string` do not implicitly convert to `Date` and `FuzzyString`. Use `new Date(...)` / `.ToDate()` and `new FuzzyString(...)` / `.ToFuzzy()`; relevance sorting selects the fuzzy field's `.Value` string.
- **File storage format:** new chunks use `BinaryStorageID` and omit `FileID`. Legacy `[BINARY_CHUNKS].FileID` keeps `[AsObjectId]` so existing chunks remain readable; legacy queries explicitly exclude chunks with a storage key. File entity `_id` storage still follows the entity mapping. Upgrade all application instances before new-format uploads; old libraries cannot resolve the new reference. No bulk migration is needed. Replacements retain legacy chunks, and interrupted/uncertain uploads can leave orphans. Legacy cleanup scans actual collections for conflicts and requires database-wide listing/read permissions, but cannot prove ownership against concurrent legacy writes or custom schemas. Reconcile ambiguity offline, never guess ownership.
- **File saves and transactions:** normal full/partial/preserving saves exclude managed upload statistics/reference from updates; full file saves atomically replace application metadata while retaining persisted upload fields, using empty upload defaults when those fields are absent. Raw `Replace`/updates can bypass protection. Stream operations read persisted references, so objects mutated inside aborted transactions do not select an uncommitted key. `Data(db)` creates a database-bound streamer per call. Index initialization is shared per client/database and awaited before upload, avoiding catalog changes racing subsequent transactions. Pass transaction sessions explicitly to streaming methods.
- **Mapped file metadata:** resolve managed-field BSON names from the concrete class map's `AllMemberMaps`, since upload fields are inherited from `FileEntity<T>` and `GetMemberMap` searches declared members only. Cascade projection lookups, legacy classification, conditional metadata deletion, and full-save preservation/default expressions must honor those names. Chunk fields retain their separate schema; do not rename them to match entity metadata. Register class maps or naming conventions before first use.
- **File metadata copies:** single/batch full saves and inserts initialize new identities with an empty upload state, including when resetting the ID to generate a new one. Binary content is not cloned. Existing identities preserve persisted upload metadata. Previously shared storage keys are not automatically reconciled; freeze writes and back up data before offline ownership repair, without deleting shared chunks.
- **ObjectId-format file IDs must be lowercase:** upload, download, explicit chunk deletion, and cascading deletes reject uppercase/mixed-case hex IDs with `ArgumentException` before touching chunks or starting cascade writes. Validate the whole eligible delete batch before scheduling any writes. Non-hex custom IDs remain supported. Do not normalize rejected IDs silently, since their string metadata IDs may name different documents. This guard preserves the chunk schema and legacy compatibility without migration; it cannot repair data already aliased/overwritten by earlier versions.
- **Cannot decorate or remap inherited `Entity.ID` per concrete type:** `BsonClassMap.RegisterClassMap<Book>(...).MapIdProperty(b => b.ID)` throws because `ID` is declared on `Entity`. To keep legacy BSON ObjectId `_id`s, map the `Entity` base member before first use (affects every `Entity` subclass), including `StringSerializer(BsonType.ObjectId)` and `StringObjectIdGenerator` for ObjectId-formatted IDs only. This strict serializer cannot write arbitrary custom string IDs, unlike `[AsObjectId]`; for mixed/per-entity storage, implement `IEntity` and own the `[AsObjectId]`/`[ObjectId]` ID property, or migrate to strings.
- **`JoinRecord` `_id` is server-generated** (upsert writes never set it), so it's a BSON ObjectId, hence `JoinRecord : ObjectIdEntity`. Don't rebase it on `Entity` (plain string ID can't deserialize ObjectId `_id`).
- **`Guid` entity IDs** need `BsonSerializer.RegisterSerializer(new GuidSerializer(GuidRepresentation.Standard))` before init (tests do this in `Tests/Init.cs`); the library does not register one. Expression/filter-based `DeleteAsync<T>` projects IDs as `BsonDocument` (not `object`) so Guid/custom-represented IDs cascade-delete correctly.
- **Deletes + global filters:** an eligibility read is only a snapshot. Filtered non-file deletes with registered relationships use per-candidate conditional deletion and cascade joins only for returned stored BSON IDs, so a concurrent exclusion preserves the survivor's joins even in mixed batches. Filtered non-file deletes without registered relationships use a direct bulk delete with the global filter retained. Check registry emptiness per operation, never cache it. Initialize relationships before concurrent deletes: registration after bulk selection does not add cleanup to that in-flight operation and can leave orphaned joins for deleted entities. Unfiltered/ignored-filter deletes retain bulk behavior; files retain conditional reference protection. Without a caller-owned transaction, failures can leave earlier entity deletions and orphaned joins; retrying is not guaranteed to repair them. Never claim cross-collection atomicity without a transaction.
- **Cascade relationship roles:** IDs can overlap across entity collections. `Cache<T>.ReferenceCollections` retains `JoinRecordRole` flags per join-collection name; cleanup matches only the registered `ParentID`/`ChildID` role, or both for self-references. Register both endpoint types, swap roles for inverse initialization, and merge repeated registrations with bitwise OR. Registration skips updates only when the cached flags already contain every requested role; this relies on flags accumulating monotonically, with no removal/reset path. Missing flags still require an atomic merge. Never restore an unconditional OR filter for different endpoint types.
- **Value-type batch IDs:** use the typed overloads `DeleteAsync<T,TId>(IReadOnlyList<TId>)`, `Many.AddAsync<TId>/RemoveAsync<TId>`, `ParentsQueryable/ParentsFluent<TId>` with `where TId : struct` (arrays like `Guid[]`/`long[]`/`ObjectId[]`). Do **not** use `IEnumerable<TId>` for those overloads; `string` implements `IEnumerable<char>` and would steal the generic method. Existing `IEnumerable<object?>` overloads remain for reference/boxed IDs.
- **Custom ID generation** = registering an `IIdGenerator` (per entity via `DB.RegisterIdGenerator<T>()`, which works for `Entity` subclasses too; or per ID type via `BsonSerializer.RegisterIdGenerator`). There is no `GenerateNewID()` to override anymore. Without a resolvable generator, string IDs silently get ObjectId-format values. Other ID types can still be cached/queried/deleted and accept manually assigned IDs; missing generators throw only when `GenerateNewID()` runs (typically save of an entity with an empty ID).
- **`HasDefaultID()` uses `IIdGenerator.IsEmpty`** when a generator is resolved (so `string.Empty` and custom empty sentinels regenerate). With no generator it falls back to comparing against the ID member's default value.
- **Generator registration timing differs by level:** `DB.RegisterIdGenerator<T>()` is order-independent (`Cache.SetIdGenerator` overrides even after first use). `BsonSerializer.RegisterIdGenerator` / class-map `SetIdGenerator` are only read during `Cache<T>` static init; they must run **before first use** of that entity type (including first save/query that touches `Cache<T>`).
- **Global conventions register via module initializer** (`Core/LibraryInitializer.cs`, not a `DB` static ctor). `Date`/`FuzzyString`/`decimal` defaults come from an `IBsonSerializationProvider`, so users can `BsonSerializer.RegisterSerializer` for those types before first lookup and win; do not rely on `TryRegisterSerializer` to override an existing different serializer (it throws). The `ModuleInitializerAttribute` shim exists because netstandard2.1 lacks it.
- **`DB.Default` / `Instance`** throw if `InitAsync` never ran for that client/name.
- **`ChangeDefaultDatabase`** is explicitly unsafe under concurrency; cancel watchers first.
- **Migration discovery** excludes many assembly name prefixes; test assembly name `MongoDB.Entities.Tests` is special-cased. Prefer `MigrateAsync<T>()` or `MigrationsAsync` when discovery is ambiguous.
- **Migration class names** must split on `_` with numeric order prefix or execution throws.
- **Library LangVersion 13** (not latest) due to DocFX; don’t bump casually without checking docs build.
- **`SharpCompress` package** is a deliberate direct reference for vuln mitigation; remove only when driver transitive is fixed.
- **Solution format is `.slnx`**, not classic `.sln`.
- **Line endings CRLF** per `.editorconfig`; preserve when editing.
- **Public docs site ≠ repo README depth**: behavioral detail lives in `Documentation/wiki/` and XML docs; verify against source.
- **Do not commit secrets.** CI compose passwords are fixtures; NuGet key is Actions secret only.

- File index initialization failures are evicted by exact cache entry, allowing later uploads to retry without a late failing caller removing a newer attempt. Successful initialization remains shared per client/database.

- **Pipeline update hooks:** both `ExecutePipelineAsync` builders invoke `OnBeforeUpdate` once before writing. Hook exceptions propagate. Hook `AddModification` calls throw `ArgumentException` before writing, including same-field and different-field combinations. Compare definition counts around the hook, not against zero: `DB.Update` adds audit definitions before execution, and rejecting those breaks existing audited pipelines. Pre-existing definition handling is unchanged. Use regular updates with modifying hooks; validation-only hooks are supported on pipelines. Never silently discard hook definitions or translate update operators into aggregation expressions.
